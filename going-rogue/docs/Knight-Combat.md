# Knight combat

Core base: [combat and cover](../../docs/Combat-Tactics.md), [commands](../../docs/Commands.md), [architecture](../../docs/Architecture.md). Mode/profile contract: [Going Rogue](../README.md). Dated checks: [validation](../Validation.md).

## Implemented ownership

Going Rogue registers `KnightCombatLayer` at priority **76** for native `Knight` brains with role `bossKnight`. Runtime eligibility additionally requires Going Rogue, a living/active registered Core follower and the local human leader. Ordinary hostile Knight, other Goons, exUsecs and other modes do not qualify. The server allows Knight invitations/spawn. [Big Pipe](BigPipe-Combat.md) now has his own layer and raid-ready definition; Birdeye remains raid-locked. The shared `GoonCombatLayer` owns eligibility, readiness, temporary suspension and cleanup for both implemented roles. This shared-lifecycle revision has local build/fixture coverage and awaits raid qualification.

The original `BossKnightLayersStrategy` remains installed. A bot-local `GoonLayerLease` temporarily removes conflicting initialized native fight/building/warning/request layers and external SAIN solo/squad layers from that bot's active-layer list. It preserves their objects and restores priority order without calling Activate again. Native grenade danger (80), weapon maintenance (78), and external SAIN danger/flashed layers retain priority. Core's peaceful requests (73) and patrol remain available after combat. No global layer removal, shared preset edits or typed SAIN dependency are used. Release restores the actual original owner, which can be native or external SAIN depending on its Goons configuration.

`KnightCombatLayer` hosts Core's combat driver with an injected `KnightCombatLogic` and action factory. The driver supplies combat activity, tracking, command routing, post-combat handoff and recorder publication. Knight's default objective runs one addon selector; it does not run a second Rifleman selector. Higher-priority danger/maintenance interrupts execution while the addon preserves the existing command objective. Final release resets it and removes native event subscriptions. Cleanup attempts each stage independently so a reset failure cannot skip layer restoration.

Core supplies the internal driver factories, friend-assembly access, shared support planner, boss tick guard and generic saved-spawn preflight/readiness/rollback. Character selection and the combat-readiness acknowledgement remain in the addon. Core has no assembly reference to Going Rogue. Other combat brains retain their normal driver lifecycle.

## Decisions and actions

`KnightCombatObjective` selects Knight's adapter; `GoonCombatObjective` owns shared commitments and assistance for Knight and Big Pipe. `KnightVanillaCombat` adapts the native `BossKnightFightLayer` selector. Its lifecycle partial translates selected native decisions into the shared execution contracts. The preserved native branch names remain in reasons prefixed `knight.native.`; shared cover reasons use `knight.cover.`. These flow through the existing combat recorder, without invoking providers just for diagnostics.

Shared Goons `committedCoverHold`/`committedPositionHold` decisions end through Core's `EndCommittedPositionHold`, matching the exact arrival transaction and deadline used during selection. They must not fall through to generic `EndBaseHoldPosition`: a delayed native cover flag can prematurely restart the same hold, while generic pressure-based extension can outlive its committed deadline. Existing prepared survival/support successors retain priority, and expiry releases ordinary medical/reload/combat reevaluation without changing Aggression or clearing living enemy memory.

The custom `coverArrival`/`supportHold` interrupt also needs concrete progress: visibility alone cannot end it into the same hold. It prepares an admitted immediate shot or shared recovery successor under pressure; failed probes back off for 0.25 seconds. Medical work and the original settle/hold deadline remain authoritative.

| Native branch or behavior | Going Rogue execution |
|---|---|
| Close enemy, first sight and exposed shooting | Knight's native choice, with shared dogfight/reload survival checks first and normal follower firing safety |
| Attack/search after lost firing opportunity | Autonomous pursuit requires distance below the shared Far band (96m), no recent recovery pressure and low threat. Ordinary PMC/Scav targets use boss-relative equipment/known-contact confidence with at most two nearby contacts; other roles retain the old low-threat gate. Unsafe pursuit uses shared shooting cover or recovery; permitted unseen pursuits use memory-only search, never a live transform |
| Fight/assault cover, two-cover assessment and corridor timing | Native branch choice; shared cover selection/admission and committed travel. Only the common owner publishes the cover destination |
| Cover arrival | Shared immediate medical handoff; otherwise 2.5-second settle, fire when valid, then bounded reevaluation |
| Damage, first aid and stim desire | Shared medical provider runs once before native selection. Native requests cannot bypass it; deferred requests retry after one second |
| Native stationary fire, hold and prone end conditions | Retained where compatible. `KnightLayAction` retains native prone/look timing and aiming with shared friendly-lane, alignment and launcher guards; it omits the native node's autonomous launcher switch. Other actions come from the common factory |
| Failed cover | Immediate safe fire if possible, otherwise bounded retry. No repeated provider probes or forced enemy-memory clearing |
| Native exposed hold (`periodWait` and related holds) | At nearby, admitted low threat without recovery pressure, use Core's remembered-position search instead of repeating recovery holds. Blocked/completed searches retry after one second. Unsafe/distant targets retain shared recovery movement/arrival or bounded no-cover fire/suppression/hold. Native holds while actually in cover retain their timing |
| Grenades and suppression | Shared admitted-target, trajectory/weapon and firing-safety contracts. Native blind post-contact smoke fire is intentionally omitted |
| Native movement/medical end handlers | Removed from the adapter; shared arrival, treatment, commitment and end logic own these actions |

Shared reload retreat, dogfight, committed grenades, medicine/heal retry and protected movement run before optional help/support or a new native decision. `medicalRetryHold` has a dedicated addon end handler before generic holds: it probes the shared medical provider once when due (or treatment is active), prepares a concrete medical successor, preserves the retry while safely positioned, and tries shared recovery movement after a failed search or under pressure. No accepted recovery cover uses Core's bounded no-cover commitment and dedicated end handler. Generic hit/under-fire hold ends cannot restart this medical hold every frame; no treatment or safety check is bypassed. A committed medical destination is never replaced by ordinary support planning. The adapter keeps its own last selected native decision because BigBrain publishes custom action identifiers.

Knight also invokes the shared combat long-gun preparation used by Rifleman after urgent reload/dogfight, grenade and medical work. An emergency pistol draw can therefore recover to a loaded rifle, or select and reload an empty rifle under the shared personal-visual/threat/controller/resource gates. An existing search or hold prepares a concrete weapon successor through Core's target-scoped decision transition instead of waiting for that action or combat to finish. Shared preparation/reload holds retain their own end handlers; the addon does not copy ammunition or reload-permission policy.

## Commands and teammate support

### Solo protection and Goon unit initiative

`GoonUnitTactics` applies a non-persistent 70% aggression / 100% determination baseline when a living, owned Knight has at least one other living, owned Goon registered to the same local human. Distance from the player does not switch this unit stance. Knight leads the existing native member-position/search policies; Pipe follows his lead and Birdeye retains sniper execution. A selected, dead, inactive, foreign or unclaimed actor cannot activate the stance. It is recomputed after ownership refresh, not by issuing synthetic player commands.

Solo Knight keeps his saved combat preferences and normal protective/help/rejoin policy. Protection does not set aggression to zero: his native nearby low-threat assault/search branches remain available, while pressure, unfavorable threats and productive cover retain their existing responses. Explicit On Your Own remains available when he is alone. The unit baseline sits below command overrides, so Hold Position, Cover Me, Regroup, Need Help and accepted pushes keep their existing authority; clearing command percentages reveals the current unit baseline. Saved proficiency is never rewritten.

The unit also supplies Knight as the members' runtime movement anchor. Pipe/Birdeye use him instead of the nearest player-side teammate for independent combat positioning, and ordinary peaceful following targets Knight even when they have no personal enemy contact. Knight anchors his own independent combat locally and still follows the player during ordinary peaceful movement. This does not reparent native/human ownership, generate contact or grant fire permission. Pending player commands, a consumed player Regroup and dependent Cover Me retain the real player anchor; invalid/foreign/dead Knight references cannot supply an anchor. Unit release clears this reference along with its percentage baseline. Independent Marksman combat does not start automatic distance-regroup, preserving Birdeye's native sniper spacing and explicit Regroup handling.

An automatic regroup that predates independence cannot retain its old player-side destination indefinitely. Core completes that obsolete objective through normal lifecycle routing once it is a regroup-owned action and the actor is grounded and free of protected medical/weapon/grenade work. A consumed player Regroup is never released by this rule; shared medical actions retain their own end handler before the automatic-release check. This clears regroup-local target/claims, not living enemy memory or unrelated combat commitments.

Losing the last partner clears Knight's unit baseline. Confirmed Knight death clears the remaining Goons' unit baselines and player-issued combat percentage overrides, restoring their saved settings and removing his coordination without electing a replacement commander. Temporary loading/ownership loss clears the addon baseline but does not count as death or erase player command overrides. Release/reset/raid teardown clears the baseline as well.

Independent Knight/Pipe retain the shared general ally-support planner, including its target/contact, stability, cover and safety gates and bounded support lifecycle. Automatic human-injury protection and boss-distance regroup are still disabled during independence; an injured player can receive ordinary ally support or explicitly request Help/Regroup. Native member orders and admitted target sharing are no longer vetoed solely by human injury while independent. Medical, personal incoming fire and explicit orders remain authoritative.

Native position orders are valid for at most eight seconds, with up to eight meters of Knight displacement and ten meters of known-enemy-anchor displacement. Lost/dead targets or expired geometry invalidate them immediately; coordinator refresh requests fresh native positions. Routine refresh does not create a new explicit directive revision, so it cannot steal a player push. These checks admit fresh decisions only and do not cancel a progressing movement leg or bypass Core's prepared transition owner.

Returning from Regroup, Help or another combat objective invalidates local positions without reinitializing the native selector. Only actual combat startup calls `Begin`; Knight's original fight-entry timestamp is preserved on objective resume. This avoids repeatedly granting the native ten-second opener during one encounter.

Knight's selected primary-combat decisions also publish target-specific autonomous advance intent. A remembered-position search, pursuit, admitted Knight combat-cover movement, or visible shootable covering fire permits Big Pipe to search toward that same target. Holds, recovery/retreat and treatment do not grant permission; objective deactivation/reset clears it. This reads/publishes actual decisions and never invokes a second selector. Explicit Knight firing-position orders and the existing player-command objectives keep their own higher-priority routes.

At fresh ordinary-combat selection, Knight and Big Pipe rejoin the human when an unseen, unshootable contact has no productive local work and the configured Core regroup distance is exceeded. They reuse the shared safe navigation/direct distance, urban-detour and recent-fight grace. Medical/grenade work, existing arrival/movement/cover commitments, visible/shootable contacts, active orders, ordered-push locks, Hold Position and unfinished weapon work keep priority. This prevents the native caution/no-cover fallback from renewing stationary recovery forever while the human advances; it does not interrupt a committed action or clear enemy memory. Birdeye uses the existing Marksman regroup policy.

Medical-retry relocation uses Core's `TryGetMedicalRetryRecoveryDecision`, shared with Rifleman and Marksman. The owning end handler still probes the provider once and prepares the concrete successor; the shared helper only selects recovery and never invokes treatment for diagnostics.

- **Regroup:** the existing Core command admission and Regroup objective own the accepted order, movement, protection and completion. A recovery hold created while the enemy was missing cannot bypass command routing after real contact returns; Core evaluates that action through normal objective interrupts again.
- **Suppression:** Knight consumes `SuppressEnemy` through Core's existing suppression objective and actions. The same target knowledge, shot-safety and termination rules apply.
- **Need Help:** the existing human boss hit/help signal and closest attacker feed shared support target admission. Knight uses immediate fire, suppression or support cover; otherwise he enters shared Regroup. Personal immediate combat, pressure, medicine and protected commitments retain precedence.
- **Ally engagement:** reuse `FollowerCombatCommon.TryGetAllyEngagementSupportDecision`, including settled-cover, contact/admission, pressure and recent-personal-sight gates. Player and follower engagements are eligible under that existing contract.
- **Nearby push:** Rifleman and Knight both use `FollowerCombatSupportPlanner`. Its push branch is extracted unchanged from Rifleman's previous implementation: current-cover/safe immediate fire, search backstop, support cover or a firing position. Keep the 45m straight/65m path bounds; no duplicate push event or copied assault destination.
- **Support lifetime:** a passive hold can end for support only with a prepared successor. Failed plans back off for one second. Support cover settles for 2.5 seconds and has an eight-second no-fire hold deadline; expiry applies a three-second retry delay. Valid firing and urgent survival work remain authoritative. A target change invalidates the prepared successor.

## Combat command willingness

Going Rogue registers `GoonCommandPolicy` through Core's immutable `CompanionCommandPolicy` bridge. Knight, Big Pipe and Birdeye always accept a valid combat `There` point order; this is willingness to move to the pointed position, not an enemy-assault order. Ordinary recruited members use their existing Go Forward acceptance roll for combat There. Gesture/range reception, loot reservations, the 30m point limit, valid navigation and protected medical execution still apply.

Knight's Go Forward willingness uses his equipment power, the target's equipment power and Core's shared threat formula (target role plus nearby living eligible known contacts). `GoonPushLeadership` caches one verdict per player command and target, evaluated with Knight's own admitted contact and equipment. Big Pipe inherits that verdict, including refusal; follower iteration order cannot produce separate confidence rolls.

Without a living, active Knight registered to the same local human's squad, Big Pipe accepts a valid admitted Go Forward order. He also accepts independently when within 30m of the player and Knight is beyond 50m from the player, actively fighting a different target, or lacks admitted knowledge of the requested target. Active engagement means visible contact, incoming fire or personal sight within 2.5 seconds; stale memory does not delegate command. Distance is checked at acceptance, then authority stays latched to that push sequence. Equipment rules, actor/target admission and movement/fire safety remain authoritative.

A fresh actionable native Knight directive may end Pipe's player push: a member recalculation requested after that push, or a published position for a new Knight engagement. Routine same-target recalculation and distance changes cannot cause takeover. The successor must pass Core's exact-point firing-position planner and admitted-target transition before the push, target lock and temporary aggression override end. It never clears living enemy memory. Healing, explosive danger, incoming fire, recent hits, useful visible fire and unfinished weapon/grenade work delay the handoff. The superseded push never resumes automatically. Player Need Help and Regroup retain priority, including Regroup already consumed into objective state.

The confidence adapter reads existing tracked positions and does not acquire enemies or run world scans. Character/player level, pickup personality, configured Aggression and Self-Determination are absent from this acceptance calculation. The formula is `70% + 30% * gearConfidence - 2% * max(0, threat)`, clamped to 10–100%; gear confidence reuses the 0.55–1.45 equipment-ratio scale, with unknown gear neutral. Invalid numeric confidence inputs refuse. Debug acceptance events retain the actual inputs, chance and roll for qualification. Independent Big Pipe still requires a living admitted target and follows normal command execution and survival gates.

`GoonCombatConfidence` gives these two assault bosses a relative combat-power multiplier of **1.5 against pmcUSEC/pmcBEAR** and **2 against ordinary assault/assaultGroup/cursedAssault/marksman Scavs**. These are confidence inputs only: actual equipment power, item scores, skills, damage, health and saved settings remain unchanged. Unknown/missing roles, bosses, guards, raiders, Rogues and other elite/event roles receive a neutral multiplier. Core's optional command policy supplies the multiplier before calculating both equipment confidence and shared threat; passive command acceptance diagnostics include the target role, multiplier and effective power. The original policy constructor remains neutral and binary compatible.

Both native-style selectors use the same addon role mapping for autonomous approach admission against ordinary targets. They require a living active target, an existing known position and personal contact history, valid native equipment powers, no weapon-threat veto and at most two eligible known nearby contacts. The existing shared threat formula must be non-positive after applying relative power and native target-role/weapon weighting. This replaces dependence on the legacy `Memory.AttackImmediately` low-threat flag for those matchups; all other roles retain the previous low-threat check. Native branch selection, distance/pressure gates, medical/reload commitments, navigation and shot safety retain ownership. This is assessment, not an unconditional push order.

Birdeye refuses combat Go Forward independently of a fallback tactic tag. Ordinary Marksman/SAINShooter followers also explicitly refuse. Successful Knight and Big Pipe pushes enter Core's ordered-push objective through `ShouldConsumePushCommand`; accepted pushes retain the existing temporary 100% Aggression override and survival/medical interrupts. Birdeye's [implemented sniper brain](BirdEye-Combat.md) retains this assault restriction.

## Native BossLogic and managed Goons

The saved-profile spawn path retains the native role and proficiency settings. Its direct `ActivateBot` call bypasses native `BotSpawner.SetBoss`; the addon therefore initializes **missing** Knight BossLogic once using the native activation method, without SetBoss's raid-bot recruitment. It preserves the existing native strategy and any existing BossKnight instance. `IamBoss` allows BotOwner to own update/disposal. Core's legacy human-boss forwarding now runs only when native boss ticking is inactive, avoiding duplicate activation/update.

While owned, scoped patches give BossLogic a view of the human's living managed Big Pipe/Birdeye, suppress automatic native recruitment, handle the one-companion positioning case and defer native cover recalculation to Knight's next safe selection. Human follower links stay intact. No ordinary exUsec or unrelated raid Goon joins this view.

`KnightSquadCoordinator` maintains native follower-position/status data and shares Knight's target through common arbitration only when that member already has the enemy admitted. It respects explicit orders, treatment, incoming fire and recent/visible personal contacts. Current-position seeds are not orders: only native position-recalculation publication creates an assignment, bound to Knight's target and the same target on the follower. Native `BossKnight.ForceRecalcShootPos` otherwise looks for Sanitar follower strategies; the scoped managed-member hook instead queues native position recalculation. Foreign/native AI groups retain their original routing.

The shared Goon objective consumes actual assignments before optional launcher/ally support or ordinary combat selection, after human help and urgent/protected work. Passive settled holds may prepare the same successor through the existing support handoff. Core evaluates the assigned candidate itself through the centralized firing-position path, displacement, floor, alternate-threat, shot-lane and navigation gates; it does not reinterpret the point as an enemy anchor or choose from unrelated ordinary candidates. Birdeye assignments retain backline/sniper constraints. Removal, death, target changes, player orders and release invalidate or suppress assignment use; human follower links remain intact. Birdeye's [sniper brain](BirdEye-Combat.md) consumes these assignments through the shared Marksman planning boundary.

## Raid allegiance and spawning

Native creation is distinct from active follower registration. During loading EFT can create Knight as `NonActive`, then calls `PostActivate` through `Bots.CheckActivation` at raid start. Core waits for that captured game's `Started` status before counting the registration timeout; the active-bot callback still owns conversion, and the addon combat claim still gates Ready. Failed setup diagnostics include native state, game status and watcher/registration state before rollback.

After successful readiness and the delayed live-state check, the shared spawn greeting requests `MumblePhrase` for native Goons, matching Core's existing recruited-boss path. Ordinary teammates retain `Ready`. The forced-phrase gate is armed for the actual actor and selected phrase only at playback.

Knight's definition is raid-ready in the server addon. Core's normal saved teammate profile endpoint and game-side activation path preserve `bossKnight`. The addon marks Goons with `GenerateEquipmentEachRaid`: the spawn endpoint calls native SPT boss generation for the active map and adopts its fresh inventory into a clone of Knight's roster identity, boss skills and recovered HP. The stored inventory is only a profile preview, never the next raid's loadout. Invite/auto-join gates accept the registered generator without requiring a permanent weapon. Raid outcome equipment/loss persistence skips these companions; ordinary teammate loadouts are unchanged. Prefetch prepares one kit for that raid; transit carries the existing in-raid kit.

After native generation, Core replaces the generated secure-container tree on the raid clone with its boss container and runs the centralized teammate medical/ammunition provisioning. This also applies in Realistic (`Extreme`) mode: Grizzly/Surv12 are supplied unless already covered by the backpack, plus ten full stacks matching the main weapon's ammunition. The generated source remains untouched. Going Rogue then checks both primary weapon slots for detachable-magazine firearms. An existing compatible magazine directly in vest/pocket grids satisfies the spare requirement, including an empty magazine for normal maintenance. Otherwise the addon creates one full spare using the installed magazine template and generated ammunition, placing it through native inventory helpers in free compatible vest/pocket space. Internal-magazine weapons and launchers are skipped. No space or invalid magazine data fails setup before saving an unusable preview. This runs only on freshly generated isolated Goons kits, never on ordinary teammates or carried transit inventory. Core only invokes the optional addon equipment callback. After provisioning, a separate copy of the resulting raid inventory replaces the saved viewing preview; subsequent raids still generate fresh equipment. Ordinary teammate Realistic rules are unchanged.

Knight keeps `IsSquadMate == false`, using the existing recruited boss-member behavior rather than saved-follower equipment manipulation. `UsesSavedCombatPreferences` separately enables his editable Proficiency, aggression and self-determination. Ordinary field recruits retain their existing baseline.

Follower-details metadata includes the saved native role. Before raid settings finish, the addon matches selected account IDs and separately reports Goons presence. Generated IDs work as well as legacy quest IDs. A scoped conversion context covers debug/recruited companions before Core registers them. Going Rogue keeps Bad Guy off from setup through transit: friendly Scav encounters and recruited-Scav diplomacy retain their shared Allegiance rules, while PMC friendship encounters remain disabled during Rogue context. Automatic exUsec friendship is explicitly disabled during initial combat testing. Legacy quest friendship outside Going Rogue is unchanged.

Selected/live managed Goons suppress normal and forced Goons waves before quest overrides can re-enable them. Core also adds all three Goons to native `BotSpawner` role exclusions before either saved-profile or legacy companion spawning, preserving existing exclusions. Direct companion activation remains available. This targets the normal/native spawning paths; arbitrary third-party direct activation is outside the native spawner gate.

Selection has an explicit unresolved state. A failed/missing/duplicate roster response cannot publish an empty selection: hostile Goons exclusion and the PMC encounter restriction stay conservative until a complete selected-role snapshot is validated. Saved-profile spawn preflight retries follower metadata three times with 250ms between failures, using the existing HTTP timeout. It requires role/tactic and every Proficiency/aggression/self-determination value for every selected account, then checks roles against fetched profiles before activation. Failure shows a localized setup message and leaves the companion unspawned; it does not substitute saved-settings defaults. Random player-Scav followers retain their existing generated defaults.

Activation is awaited instead of using an async-void profile loop. The active-bot callback must return a registered follower within eight seconds; the addon then has a bounded ten-second combat-readiness wait. Knight acknowledges only after his driver, native BossLogic, layer suspension and coordinator have initialized successfully for the same actor. Missing addon readiness, changed identity/role, null registration and timeout are failures. The delayed Ready phrase rechecks both registration and combat ownership immediately before speaking.

Failed setup releases addon ownership, pending/registered membership, human death hooks, watcher/social/equipment-cache state and uses native `BotLeaveData.RemoveFromMap` for despawn. A cleanup-only follower dismissal runs after disposal; this is not a death/escape database result. Cleanup stages are independent, with native disposal/despawn fallback. Raid identity guards prevent an old asynchronous completion from publishing selection, displaying a new-raid error, or removing a newly spawned actor that reuses the same saved profile ID.

ExUsec friendship/recruitment, trader/quest progression and removal of PMC request flows remain later work. Virtual's Custom Quests is not a combat dependency.

### On Your Own pursuit

For Knight, Big Pipe and Birdeye, combat On Your Own applies exactly 70% temporary aggression and 100% determination through the existing battle-wide command lifetime. Saved percentages are untouched and restore through the shared reset. Combat independence releases the ordinary escort distance/low-threat pursuit veto. Shared urgent weapon, medical, explosive and damage handling still precedes pursuit. Knight advances toward admitted remembered contacts through Core's bounded contact-advance planner; unseen targets never supply a live transform. Safe distant steps can run through the existing sprint/run gates. Native close fighting remains available at the final ten-metre envelope. Actual published pursuit marks Knight as searching for Pipe's group-follow policy. Automatic human-protection diversion and optional escort fire-support planning do not repeatedly replace this independent pursuit; explicit Regroup/Need Help remain Core objectives.

Settled idle/recovery holds may hand off after 2.5 seconds, at most once per 0.75-second probe. The successor is planned and prepared before clearing cover/position/movement or publishing its destination. Unknown/dead/searched contacts, blocked paths, useful shots, medicine, reload/switch work, danger and explicit orders do not authorize that handoff. Search tracking begins only with the published decision and ends without exhausting memory on objective/command release. Ordinary battle override resets retain the existing lifetime. Birdeye's shared Marksman end provider gets first refusal before an optional pursuit hold handoff.
