## Brain and native comparison

`BirdEyeCombatLayer` is a role/brain-scoped BigBrain layer for living, registered Going Rogue followers with a local human leader. It uses the same readiness gate, Core action driver and reversible native-layer lease as Knight and Big Pipe. Both native `BirdEyeFightLayer` and `BirdEyeHoldLayer` are suspended while owned; danger and malfunction layers retain priority. Release restores initialized layers without activating/subscribing them again. Ordinary hostile Birdeye and other modes retain their existing behavior.

The old plugin's `BirdEyeFightLayer` largely delegated to `FollowerSniperLayer`, adding close defensive/holder behavior and secondary switching. The current native `BirdEyeAbstractLayer` supplies a **60m preferred / 40m minimum** firing geometry; its fight layer combines stationary fire, cover/firing-point search and a team-triggered aggressive approach. The native hold layer controls a selected firing area with separate searchers.

The managed brain keeps that sniper geometry through `BirdEyeSniperPositioning` and uses Core's actual `FollowerCombatSniper` for combat execution. The character callback runs only at fresh planning, after medical/urgent work, close weapons, arrival/movement commitments and player Need Help. It selects a shared shooting-cover candidate around the native preferred position, then requires Core's exact-point firing-lane, floor, alternate-threat, standoff, displacement and complete-path admission. Unknown/non-finite targets are refused. Rejected candidates fall back to ordinary Marksman selection; probing is limited to once per second. Native finder publication and blind team-triggered rushing are replaced by these shared transactions.

## Weapons and commands

Close defense and eligible proactive automatic support use Marksman's existing loaded secondary/holster admission, penetration/threat policy, bounded draw/readiness hold and concrete safe movement. A useful current-weapon shot retains priority. An automatic secondary remains selected in close danger; normal-range sniper support returns to the primary after the threat leaves that range. Birdeye positions use the existing `sniper.FireSupport.position.*` intent, so weapon return and firing-position arrival adjustment/wait retain the same owning code. Reloads, ammunition, medicine, grenades and shot safety have no separate Birdeye implementation.

Before follower initialization, a scoped addon patch assigns the runtime Marksman tactic for local Going Rogue Birdeye. This precedes proficiency-template capture and enables Core's Marksman suppression/Need Sniper routing without editing the saved locked tactic. Native generated skills and the existing Proficiency controls retain their current contracts.

Birdeye accepts There, Regroup, Need Help and Need Sniper through Core. Suppression uses the existing admitted automatic-secondary fallback when available. He retains the sniper refusal for assault Go Forward. The player/50m delegation rules for Pipe's offensive push do not turn Birdeye into an assault follower.

Knight's published firing assignment takes priority over Birdeye's autonomous distance preference when ordinary planning is available. It must match the current admitted target and pass Core's backline/Marksman position gates. Player-distance regroup remains the fallback when there is no qualifying active Goon engagement; active Goon support can plan before that automatic fallback. Ordinary useful-shot, pressure and committed-cover routing still runs before that regroup choice, and active movement is not interrupted by distance alone. Knight's admitted-target sharing uses the existing same-human coordinator. Human ownership remains intact; player commands, including consumed Regroup and Need Help, urgent work and productive fire protect their current tasks. Birdeye follows independently through Core when Knight is absent or unavailable.

## Profiles and qualification

The server marks Birdeye raid-ready and hides his top profile statistics. Existing native raid kit generation, last-kit preview, boss container/reserves, Proficiency-only editing, fixed gear/donation restrictions, native spawn-inventory protection and no loot returns apply. Birdeye uses the same one-time automatic test-roster seed as Knight and Big Pipe. Existing members are acknowledged without duplication; removing a seeded member preserves the receipt and does not grant him again.

Production fixtures cover the addon policy, native geometry, Knight assignment, guarded routing, secondary preparation/retention, primary return, shared arrival behavior, lifecycle and native-layer restoration. Installed metadata checks resolve the compiled EFT/Core/BigBrain APIs and the follower Init patch. Native navigation, actual weapon draws/reloads, simultaneous Goons fights, suppression/Need Sniper reception, external SAIN configurations and command timing require live raid qualification. See [validation](../Validation.md).

## Team engagement

After shared survival, weapon, productive current fire, commitments and player-help priorities, Birdeye owns autonomous support selection. Knight is first, Big Pipe second, and the player third. If Knight and Pipe are actively engaging the same target, Pipe's advance/firing sector wins. Different targets retain Knight's priority. A dead, inactive, unclaimed, foreign-human, medically occupied or disengaged Goon cannot reserve priority. A Goon must be visibly fighting or have a published advance/covering-fire intent for that exact target. Merely being present or retaining an idle enemy does not qualify. The target also needs a living, admitted report in Birdeye's own tracked contacts. No missing contact is fabricated.

This covers all compositions: solo Birdeye supports the player's current engagement or works his own admitted contact; with one Goon he supports that actor's active fight; with both he uses the hierarchy and same-target exception. Explicit Knight firing-position orders retain their existing priority and safety gates. Active Goon support may plan beyond the ordinary player-distance regroup trigger; explicit Regroup, danger, medicine, reloads and useful current fire remain authoritative.

Firing geometry uses the selected ally's sector and the native 60m preferred distance, with the existing exact-point sniper/backline/lane/floor/navigation checks and a 40m minimum. Failed probes alternate a small 10m lateral offset rather than asking for the identical sector indefinitely. After two failed firing-position probes, a safe short reacquisition step may close toward the admitted report, at most 20m and stopping at least 40m away. It is movement, not a firing position or permission to shoot. No-position holds expire into fresh bounded planning instead of repeatedly bypassing the companion owner through generic Marksman support. New planning is limited to once per second. Native/independent pursuit remains available when no qualifying engagement owns support.

Successful support/reacquisition publication emits passive `birdEye.support / positionCommitted` diagnostics with the selected source and target. Rejected plans do not change the goal enemy or publish movement. Generic Core ally/push support is suppressed only for this injected companion owner; ordinary Marksmen are unchanged.


### On Your Own

Independent Birdeye can close on a distant admitted contact in bounded navigation steps instead of repeatedly selecting a stationary sniper fallback. He retains the native 60m preferred sniper envelope and Knight's advance permission; the dedicated support/reacquisition policy retains its 40m minimum. Assigned Knight firing positions, useful shots, close secondary handling, medicine, reloads and explicit commands retain priority. Automatic human-protection diversion is disabled by independence, while explicit Need Help remains available. The shared Marksman end provider runs before an optional safe idle-hold handoff; ordinary sniper positioning resumes when no independent step is appropriate.
